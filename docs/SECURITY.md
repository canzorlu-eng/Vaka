# Security

## Separation of environments

| | development | staging | production |
|---|---|---|---|
| Postgres / Redis | docker-compose.dev.yml (localhost only) | `vaka-staging-db` / `vaka-staging-redis` | `vaka-db` / `vaka-redis` |
| Google OAuth client | its own (redirect `http://localhost:8001/...`) | its own | its own |
| Gemini / OpenAI | personal/dev project, low budget | own project, low budget | own project, budget alerts |
| iyzico | sandbox | sandbox | live |
| `SECRET_KEY` | random per developer | generated by Render | generated by Render |
| Backup bucket prefix / key | none | `vaka/staging` (own token) | `vaka/production` (own token) |
| Alert webhook | none or personal | staging channel | production channel |

Rules: no production key ever lives in `.env` files, CI secrets or chat. `backend/.env` is git-ignored; only `.env.example` is committed.
Staging uses the iyzico **sandbox** (`IYZICO_BASE_URL` is set in the staging env group) so it cannot charge real cards.
Docs are disabled in production (`/api/docs` 404).

## Secrets inventory

| Secret | Where it is used | Stored | Owner console |
|---|---|---|---|
| `SECRET_KEY` | signs the OAuth state cookie | Render (`generateValue`) | Render |
| `DATABASE_URL`, `REDIS_URL` | app, cron jobs | Render internal links (`fromDatabase`/`fromService`) | Render |
| `GOOGLE_CLIENT_SECRET` (+ client id, not secret) | OAuth code exchange | Render `sync: false` | Google Cloud Console |
| `GEMINI_API_KEY` | LLM calls | Render `sync: false` | Google AI Studio / Cloud |
| `OPENAI_API_KEY` | TTS | Render `sync: false` | OpenAI platform |
| `IYZICO_API_KEY`, `IYZICO_SECRET_KEY`, `IYZICO_WEBHOOK_SECRET` | payments, webhook signature | Render `sync: false` | iyzico merchant panel |
| `IYZICO_PLAN_*` | plan reference codes (identifiers, not secrets) | Render | iyzico / `scripts/iyzico_setup.py` |
| `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` | backup upload (restore: read only) | Render cron jobs | R2 / B2 / S3 |
| `ALERT_WEBHOOK_URL` | alerts (a bearer URL: treat as secret) | Render | Slack/Discord |

Keep a second copy of this inventory (names + where to regenerate, no values) in a password manager.

## Rotation

Rotate on a schedule (yearly, or quarterly for the AI keys) and immediately on any suspicion. Always: create the new credential first,
deploy it, verify, then revoke the old one (zero downtime), except for a confirmed leak (revoke first).

- **Google OAuth client secret**: Cloud Console -> APIs & Services -> Credentials -> the web client -> *Add secret* (Google allows two active) -> put the new value in `GOOGLE_CLIENT_SECRET` on the service, redeploy, test a login -> disable/delete the old secret.
- **Gemini key**: AI Studio (aistudio.google.com/apikey) -> create key in the same project -> update `GEMINI_API_KEY` -> verify a chat turn -> delete the old key.
- **OpenAI key**: platform.openai.com -> API keys -> create (project-scoped, restricted to *Audio* if possible) -> update `OPENAI_API_KEY` -> verify `/api/tts` as a pro user -> revoke the old key.
- **iyzico**: merchant panel -> *Ayarlar / Settings -> Firma Ayarlari / API keys* -> regenerate the secret key; the new key invalidates the old one immediately, so update `IYZICO_SECRET_KEY` (and `IYZICO_WEBHOOK_SECRET` if separate) in the same minute and watch for 401s from `/api/billing`. Do it in a low-traffic window and re-check the webhook signature setting.
- **`SECRET_KEY`**: change the value in Render and redeploy. Effect: in-flight OAuth logins (10-minute state cookie) fail once; login sessions are database tokens and survive. Generate with `python -c "import secrets;print(secrets.token_urlsafe(48))"`.
- **Database password**: Render -> `vaka-db` -> *Info* -> reset/rotate the credentials (or create a new user) -> the `fromDatabase` link updates the web service; redeploy both the web service and the cron jobs. Old internal URL stops working, so expect a short error window; do it when idle.
- **Redis (Key Value)**: no sensitive data; rotate by recreating the instance if the URL leaks (cache is disposable).
- **Backup bucket token**: create a new scoped token in R2/B2/S3, update the cron jobs, trigger `vaka-backup`, then revoke the old token.
- **Alert webhook**: regenerate the incoming webhook in Slack/Discord, update `ALERT_WEBHOOK_URL`.

## If a key leaks

1. **Revoke/rotate it now** (above); do not wait to understand the scope. For the DB or `SECRET_KEY` also run `DELETE FROM auth_sessions;` if session theft is possible.
2. Find the exposure: git history (`gitleaks detect`), CI logs, screenshots, chat. If it was committed, rewrite is not enough - the key is burned; rotation is the fix.
3. Check provider usage dashboards for the exposure window (Gemini/OpenAI spend, iyzico transactions, bucket access logs); `llm_usage` shows our own spend ledger.
4. Check app logs for unusual `request_id` bursts; the daily cost alert is the canary for abused AI keys.
5. If personal data may have been accessed (DB URL, backup bucket, admin session): follow KVKK/GDPR breach duties (notify the authority within 72 hours where required) and tell affected users.
6. Write down what allowed it and add a control (scoped key, spend limit, secret scanning).

## Dependency and code scanning

- CI: `pip-audit -r backend/requirements.txt` (blocking), `npm audit --omit=dev --audit-level=high` (advisory), `gitleaks` on full history (blocking), `ruff` with `S` (bandit) rules.
- Dependabot (weekly): pip, npm, docker, github-actions (`.github/dependabot.yml`). Merge security updates within a week; run the staging smoke test after.
- Base images are pinned by major tag (`python:3.12-slim`, `node:22-alpine`, `postgres:16-alpine`); Dependabot proposes digest/tag bumps.
- The app image runs as a non-root user (uid 10001); the backup image as uid 10002. Containers hold no secrets at build time.
- HTTP hardening is in `middleware.py`: strict CSP (`script-src 'self'`), `X-Frame-Options: DENY`, `nosniff`, referrer policy, HSTS on https, body size limit, per-IP and per-route rate limits, CSRF origin check, cookies `HttpOnly; SameSite=Lax; Secure`.
- Postgres is reachable only on Render's private network (`ipAllowList: []`).
